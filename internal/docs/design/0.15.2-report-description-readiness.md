# Flash report description readiness for 0.15.2

The 0.15.2 firmware GUI requires a nonblank report description and sends it to
the Pages API after browser approval. The API stores the exact text on the
request row so notification retries use the same description. The email worker
places it in a plain-text `Description` section, normalizing CRLF/CR to LF and
removing control characters. Existing app versions can still upload reports
without a description; historical ZIP downloads are unchanged.

Before publishing freemkv Flash 0.15.2, keep this order so the Pages API never
runs against a database without the new column:

1. Dispatch **Configure private flash reports** from the marketing `dev` ref.
   It checks and applies the migration to preview and production D1, then
   configures the Pages bindings and publishes the private email worker from
   that revision. Wait for the workflow to finish successfully before proceeding.
2. Merge marketing `dev` to `main` and wait for the Pages deployment, which
   publishes the new description endpoint and notification logic.
3. Release the firmware 0.15.2 build after the site and worker accept and notify
   reports with descriptions.

The migration adds a `NOT NULL` text field with an empty default, preserving
existing rows. No historical blank report is rejected or rewritten. Test email
delivery with mocked bindings; do not use the production report smoke test for
this feature.
