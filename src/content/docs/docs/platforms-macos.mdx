freemkv comes in two builds for macOS. **Install one or the other**; both are the `freemkv` command and use the same ripping engine. Choose **Apple Silicon** or **Intel** for your Mac on the **[Download page](/download/)**.

- **freemkv** (the app): a native desktop app plus every CLI command.
- **freemkv CLI**: the command line only, as a single binary.

## Requirements

- macOS 11 or later.
- An Apple Silicon (`aarch64`) or Intel (`x86_64`) Mac. Homebrew picks the right build.
- [Homebrew](https://brew.sh). On macOS, freemkv installs through Homebrew only.
- An optical drive. See [OEM (stock) drives](/docs/drives-oem/) and [Unlocked drives](/docs/drives-unlocked/) for drive support.

## Install

### App

```bash
brew install --cask freemkv/tap/freemkv
```

This installs `freemkv.app` and puts `freemkv` on your PATH. Open freemkv, select a disc, image or folder, choose the titles and tracks, select an output location and press **Rip**. You can also drag a supported media file onto the window.

The app includes the full CLI: run `freemkv disc:// mkv://Movie.mkv` in any terminal; a bare `freemkv` opens the window.

### Command line only

```bash
brew install freemkv/tap/freemkv-cli
freemkv --version
```

A bare `freemkv` prints usage. See the [CLI reference](/docs/cli/) for ripping commands and options.

The `freemkv` cask and `freemkv-cli` formula both provide `freemkv`, so uninstall one before installing the other.

## Why Homebrew only

freemkv is ad-hoc signed, not notarized by Apple (notarization needs a paid Apple Developer Program membership). macOS blocks such an app when it is downloaded in a browser. Homebrew installs it without that block, and checks every download against a pinned SHA-256 from the [tap](https://github.com/freemkv/homebrew-tap), so it is the supported way to install freemkv on a Mac.

## Update or remove

| Installation | Update | Remove |
|---|---|---|
| App | `brew update`, then `brew upgrade --cask freemkv/tap/freemkv` | `brew uninstall --cask freemkv/tap/freemkv` |
| CLI | `brew update`, then `brew upgrade freemkv/tap/freemkv-cli` | `brew uninstall freemkv/tap/freemkv-cli` |

Upgrading from `freemkv-app` or the old `freemkv` formula: `brew update` renames them to `freemkv` (cask) and `freemkv-cli` (formula) automatically.

Settings and ripped movies are separate from program files, so updating or removing freemkv leaves them in place.

## File locations

| What | Location |
|---|---|
| Desktop settings | `~/Library/Application Support/freemkv/gui-settings.json` |
| Desktop diagnostic log | `log.txt` in the same folder, written only when the app's log level is **Verbose** or debug messages are on |
| Finished movies | The output location you choose before ripping; the desktop app suggests `~/Movies` |
| AACS keys | See [Decryption Keys](/docs/decryption-keys/) |
| CLI diagnostic log | Off by default; `--log-level 3` writes `log.txt` in the current folder |

To capture a CLI log at a specific path:

```bash
freemkv info disc:// --log-level 3 --log-file "$HOME/Desktop/freemkv-log.txt"
```

Use the path to your downloaded binary if you did not install it with Homebrew.

## Drive access

freemkv uses IOKit to obtain exclusive access to the optical drive. It unmounts the disc before direct reads, so the disc disappearing from Finder while ripping is expected. Devices appear as `/dev/diskN`.

Close other software using the disc. If access fails, reconnect the drive and try again.

## freemkv-library

For automatic ripping through a browser, see [freemkv-library](/docs/library/). It ships as a Docker image.

## Troubleshooting

- **macOS blocks the app or CLI:** review [First launch](#first-launch).
- **The disc disappears from Finder:** freemkv unmounts it to take exclusive drive access.
- **No drive is available:** check the connection, close other disc software and review [Drive access](#drive-access).
- **A movie is missing:** check the output location selected for that rip.
